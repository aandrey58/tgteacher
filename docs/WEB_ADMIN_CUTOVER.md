# Stage 9.6 — приёмка и переключение веб-админки

Статус: кандидат на staging, не разрешение на production cutover. Ветка english-adaptation; основной Telegram-бот и 45 MCP-инструментов должны сохраниться. Автоматические тесты не отправляют реальные Telegram-сообщения и не создают платных запросов.

## Матрица функционального соответствия

| Старый раздел / сценарий | Веб-эквивалент | Особенность |
|---|---|---|
| Группы, фильтры, архив, восстановление | Группы слов | Фильтры по точным меткам доступа; просмотр доступных VIP групп включает FREE |
| ZIP, шаблон, выгрузка | Группы / черновики | Импорт сначала черновик; публикация отдельно |
| Ученики, поиск ID, профиль, удаление | Ученики | Поиск по ID и имени, подтверждение удаления |
| Прогресс ученика, этапы и ответы | Ученики / детализация | Текущие задания и независимая история FSRS |
| Новые / неактивные пользователи, Excel | Настройки / подписки и отчёты | Ограничение 10 000 строк, диапазоны и период неактивности |
| Анализ групп, выгрузка прогресса | Отчёт по группе | Выполненные задания и верные ответы, не прогноз |
| VIP, подарки, отзыв, продление | Ученики / подписки | Ревизии, подтверждения, операция с защитой от повтора |
| Тарифы и история платежей | Подписки и отчёты | История БД; не онлайн-сверка платёжного провайдера |
| Рассылка, личное сообщение | Рассылки / выбранные ученики | Текст, изображение, MP4, утверждённые типы документов; очередь, статусы |
| Вопросы и ответы | Обращения | Отправка через очередь; старый индекс импортируется отдельно |
| Администраторы | Настройки | Telegram-список и независимые веб-аккаунты |
| Состояние сервера, снимки, выгрузка | Настройки / отчёты | Измеренные снимки; без доступа к raw-логам |
| Логи, справка по метрикам | Безопасный журнал / пояснения | Только категория, время, уровень; raw-логи серверные |

Открытые различия: старые ответы поддержки поддерживали Telegram audio/voice/sticker. Веб поддерживает текст, фото, MP4, документы, MP3, голосовые OGG Opus и статичные WebP-стикеры. Стикеры без подписи, анимированные TGS и видео-стикеры WEBM пока не поддерживаются. Допустимая длительность MP3/Opus до 10 минут; размер до 16 МиБ (действуют также ограничения MP3-валидатора), WebP до 512 КиБ, одна сторона 512 px. Старые ответы и их вложения нельзя восстановить из индекса. Прямой просмотр raw-логов намеренно заменён безопасным журналом. Сверка фактических платежей и физический iPhone/Android остаются staging-проверками. Визуальная приёмка по исходным референсам — отдельный ручной gate; скриншоты CI не означают подтверждённое визуальное соответствие.

## Подготовка

1. Зафиксировать SHA кандидата и убедиться, что оба job в GHA успешны. Скачать admin-browser-evidence и проверить все десять разделов, мобильные меню, редактор, роли.
2. Сохранить резервную копию БД (pg_dump -Fc), families, bot/exports, runtime_cache, admins.txt и старого индекса вопросов; проверить восстановление на изолированной БД.
3. В отдельной staging-среде запустить admin и MCP. Проверить HTTPS, точный WEB_ADMIN_ORIGIN, лимиты входа, отсутствие публичных портов DB/MCP/admin. Создать персонального владельца и проверить вход до отключения аварийного ключа.
4. Проверить учебный бот: /start, группы, все восемь этапов, FSRS, VIP покупка/история, настройки, помощь. Прогнать отдельные аккаунты owner/editor/support. Подтвердить один контролируемый тест доставки и платежей только в staging.
5. Согласовать отсутствующие форматы и безопасный журнал. Назначить дежурного поддержки. До переключения обработать текущие вопросы в старой группе, сохранить индекс, остановить старый polling, сделать dry-run импорта (см. WEB_ADMIN_ROADMAP). Не выдавать архивные вопросы за новые открытые обращения.

## Переключение (только после приёмки)

В .env проекта установить TGTEACHER_LEGACY_ADMIN=0, TGTEACHER_WEB_SUPPORT=1, TGTEACHER_WEB_ADMIN_URL=https://<ваш-домен>. URL только для одобренных Telegram-администраторов, не заменяет веб-авторизацию. Оставить текущие изображения контейнеров и PostgreSQL. Проверить compose config --quiet, затем docker compose up -d --no-deps --force-recreate bot. Проверить новые меню, старые кнопки, сохранение вопроса перед ACK, очередь, снимки, список администраторов и отсутствие дублирующих ответов. Не включать одновременно два polling-процесса.

## Откат интерфейса на том же релизе

Остановить новые действия в веб-коммуникациях. Убедиться, что pending/sending завершены или отменены через UI, а uncertain проверены вручную (не повторять автоматически). Обработать открытые вопросы веб-инбокса: они не возвращаются автоматически в Telegram-группу. Сохранить БД и индекс. В .env восстановить TGTEACHER_LEGACY_ADMIN=1 и TGTEACHER_WEB_SUPPORT=0, затем docker compose up -d --no-deps --force-recreate bot. Проверить возвращение Telegram-меню и старой маршрутизации, не удаляя веб-данные. Web delivery/snapshot jobs продолжают работать независимо от флагов. Для отката версии программы/schema использовать отдельный RELEASE_RUNBOOK и резервную копию, не старый бинарник поверх новой схемы. Никогда не использовать down -v.

## Критерии закрытия 9.6

- Паритет или явно согласованные исключения; автоматическая проверка режимов и отката на том же релизе.
- Успешная регрессия PostgreSQL, Docker, 45 MCP, Chromium/WebKit на точном SHA.
- Ручная проверка визуального соответствия референсам и staging на реальных устройствах.
- Приёмка оператором, резервное копирование, rehearsal переключения и отката. До этого production-флаги остаются прежними.
